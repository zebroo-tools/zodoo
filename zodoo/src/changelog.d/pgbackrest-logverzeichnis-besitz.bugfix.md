pgBackRest writes its log files again when something on the host has taken the log directory away from it. On cicd-3dm an hourly `chown` cron handed `$HOST_RUN_DIR/pgbackrest.logs` to the operating user; pgbackrest runs as uid 999 and from then on wrote no log file at all ("unable to open log file ... Permission denied"), while the WAL archive kept running - so nothing looked broken until someone needed the log. The ownership of the log directory is now restored before every pgbackrest command, the same way as for the certificate directory, with one line when it had to be corrected.
