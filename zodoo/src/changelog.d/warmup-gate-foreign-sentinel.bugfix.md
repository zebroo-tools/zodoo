Fix the host-side warmup gate in `odoo update` when the sentinel `proxy_exchange/warmup_in_progress` already exists and belongs to root. The odoo container creates it as root when the web role respawns; `Path.touch()` on that file then failed with `[Errno 13] Permission denied` for the host user, visible as a `[warmup gate] could not touch …` warning. The host now writes the sentinel with `atomic_write_text()` (temp file + rename, needs only write access to the directory) and sets mode 0644 so the proxy's nginx workers (nobody) can still open it. No permissions on the directory or other files change.
