Background uploads after `odoo build` (`~/.odoo/run/<project>/jobqueue/`) are processed again for projects driven through `-p`, `-xs` or `-xd`, and for checkouts whose directory name differs from the project: the detached `odoo run-crontab` now gets the same project name and restrict files as the build. Before, it resolved another project ("processed 0 job(s)") or stopped at the directory name check, and the queue grew without end. A failed upload is now retried by the next `odoo run-crontab`, up to `ZODOO_JOBQUEUE_MAX_ATTEMPTS` (default 3) attempts, not before `ZODOO_JOBQUEUE_RETRY_DELAY_MINUTES` (10) and only for jobs younger than `ZODOO_JOBQUEUE_RETRY_MAX_AGE_HOURS` (24). Before, one failure (e.g. a 401 from the registry) lost the upload for good. To check: look at `jobqueue/log/worker_*.log` after a build; it should name the uploaded images instead of "processed 0 job(s)".
